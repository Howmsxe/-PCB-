## 0. 这份仓库是什么

这是一个**用传送带送料、光电传感器检测、舵机分拣、摄像头识别颜色与形状**的物料分拣机项目。机器把混在一起的小件物料（不同形状、不同颜色）一件一件分开、识别、然后推进对应的收集箱。

**分工结构**（谁负责什么，后面每一章都围绕这个展开）：

| 部分 | 负责硬件/软件 | 说明 |
|---|---|---|
| 送料与下料 | 两条传送带（步进电机 + 驱动器） | 带1 把料送到识别位，带2 把识别完的料送到分拣位 |
| 检测 | 两只对射式光电传感器 | 上光电：料到达识别位；下光电：料到达分拣位 |
| 执行 | 3 路舵机（PCA9685 十六路舵机板驱动） | 臂1、臂2 分拣入箱，料盘给带1 供料 |
| 控制核心 | STM32F103C8T6 主控板（我们自己画的 PCB） | 跑全部电机/传感器/UI 逻辑 |
| 人机交互 | 0.96 寸 OLED 屏 + 旋转编码器 + 串口 | 屏上看状态、旋钮调参数、串口接上位机 |
| 识别 | 摄像头 + 上位机程序（PC 上跑） | 识别形状与颜色，把"放进几号箱"告诉主控 |

**一句话流程**：料盘把料倒到带1 → 带1 送到识别位（上光电触发）→ 通知上位机拍照识别 → 带2 把料送到分拣位（下光电触发）→ 上位机发"选几号箱"命令 → 两个舵机臂把料拨进对应箱子 → 回环，处理下一件。

- **12V**：步进驱动器、舵机供电、LED 发光板。这是功率最大的回路，走线要粗。
- **5V**：可由 12V 降压得到（LM2596 模块即可），供舵机板逻辑等。
- **3.3V**：主控 STM32 与 OLED 等信号侧使用，由 5V 经 AMS1117-3.3 降压。
- 功率地（12V 回路）与信号地（3.3V 回路）最终要**单点共地**，不要搞出多点地环路。

### 3.2 光电传感器接口（最容易接错，重点看）

光电传感器是 **NPN 集电极开路输出**：它自己只会"导通拉低"或"截止放开"，**不会输出高电平**。所以必须有外部电阻网络：

```
光电输出 ──[30kΩ]──┬── 3.3V（上拉 4.7kΩ）
                    ├── 100nF ── GND（滤波）
                    └── PB1（或 PB0）
```

关键点：
- 当前口径（2026-10-30 定稿）：**高电平 = 有料**（`SENS_ACTIVE_LOW = 0`）。无料时传感器导通把节点拉到低；料挡住光路后传感器截止，节点被上拉电阻拉到高。
- ⚠️ **硬件背景（必须知道）**：这个「高有效」口径**不是设计本意**——它和心跳灯被移除一样，是**板子芯片发生短路后不得不做出的妥协**（损坏后的可行方案），不是最佳实践。写新代码时：①不要把「高有效传感器」当成正常经验到处套用，常规 NPN 对射光电的标准做法是低有效；②选新功能的引脚前，先用万用表确认该引脚没有短路/损坏；③如果以后重新打板修好了短路，应把传感器接回常规低有效接线（软件把 `SENS_ACTIVE_LOW` 改回 1），并恢复心跳灯。
- 白线接 GND（`SENS_WIRED_WHITE_TO_GND = 1`）。
- 软件还做了 **8 次采样多数表决**（`SENS_SAMPLE_N = 8`）+ 10ms 去抖，抗毛刺。
- 主循环判定门槛：连续有效电平 **≥40ms** 才算一件料（`QV_LOW_MS`，硬编码不可调）。
- 如果机器一上电就狂判"有料"、带1 刚启动就停：**第一嫌疑就是光电极性或分压电阻不对**，用万用表量节点电压对照上表。

### 3.3 预留脚怎么用（你以后加功能）

空闲脚 PA0/PA4~PA8/PA11/PA12/PB2~PB4/PB6/PB7/PB13/PC13~15 都可以拿来做新功能（比如 LED 发光板控制、急停检测）。

> ⚠️ **PA0 特别提醒**：PA0 曾经当过心跳灯，后因**板子芯片短路**被移除（见 §10 第 11 条）。本板发生过芯片短路事故，**任何新功能选引脚前，先断电用万用表量该脚对 VCC/GND 的阻值**，确认无短路再写代码；不确定的脚宁可换一个。

**加新功能的标准流程**：
1. 在 `Core/PinMap.h` 加引脚宏；
2. 在 `Bsp/BoardPorts.h` 的 `BOARD_PIN_INIT` 表登记初始模式；
3. 在对应模块代码里读写；
4. 两个工程编译 0E/0W，双 hex 一致。

## 4. 机械结构（★ 前任血泪教训，务必照做）

这部分是上一任反复强调的**结构设计红线**，每一条背后都是实际翻车换来的。

### 4.1 传送带：用 3D 打印链式结构 + 齿轮传动

- ❌ **不要**用"一整块布 + 两根轴"的做法：布带会跑偏、打滑、松垮，轴的扭矩传递还依赖布与轴的摩擦，迟早打滑。
- ✅ **要**用 3D 打印的**链节式输送带**（像自行车链条那样一节一节拼），配**齿轮**驱动。齿轮与链节啮合，传动不打滑、不跑偏。
- 链节打印公差建议：节距误差控制在 ±0.2mm 内；打印后逐节检查毛刺，毛刺会卡链。
- **同轴度是生命线**：主动轴和从动轴必须严格平行、同心度好，否则链条会爬齿、跳齿。装配时用卡尺量两端轴距差 ≤0.5mm，再上紧。

### 4.2 连接件：拒绝"几颗会滑动的螺丝"

- ❌ 几颗普通螺丝硬拧的连接：振动后松动、错位，机器跑几天就散架。
- ✅ 结构件之间用**牢靠的连接方式**：
  - 优先**一体成型的套件**（把两个零件设计成一个打印件，中间用结构肋加强）；
  - 需要在架构上固定的地方，**在架构件上预先开孔**，用螺丝+螺母（配弹垫/防松螺母）或过盈销固定，而不是夹持；
  - 3D 打印件之间的拼接用**定位销 + 螺栓**组合：销负责定位（吃剪切力），螺栓负责紧固（吃拉力），各司其职。

### 4.3 先建模、定尺寸，再打印（顺序不能反）

- 任何结构件动手之前，**必须先在 CAD（FreeCAD/SolidWorks/Fusion360 或嘉立创 EDA 3D 模块）里建模装配一遍**：
  1. 量好现有器件的实际外形尺寸（舵机、步进、轴承、链节），建模时用真实尺寸；
  2. 在模型里检查干涉、检查轴距、检查链条张紧行程；
  3. 尺寸定稿后才去切片打印。
- 3D 打印缩水：PLA 约缩 0.3~0.5%，孔位建议按 +0.2~0.3mm 设计或打印后扩孔。

### 4.4 舵机安装：高度必须可调，用可调节关节

- ❌ **不要**用固定连接件把舵机焊死在一个高度上——托盘高度、箱口高度一变，舵机臂就够不着了。
- ✅ 自己设计**可调节的关节结构**：
  - 舵机座做成带长槽的支架（高度可上下滑动后锁紧）；
  - 舵机臂与拨料杆之间用可调角度的关节（球头/万向节或可调夹块），拨料角度可以微调；
  - 调好后用定位销或双螺母锁死，防止运行中漂移。

## 5. 开发环境搭建（从零开始）

### 5.1 装软件

1. **Keil MDK**（µVision5，MDK-ARM）：装官方版，激活后支持 STM32F103（M3 内核）。本工程用 **armcc5** 编译器（工程文件里已配好），如果你的 Keil 版本默认是 AC6 编译器，请在 Project → Options → Target → ARM Compiler 选 **Use default compiler version 5**。
2. **ST-Link 驱动**：装 ST 官方 ST-LINK Utility（带驱动），设备管理器里出现 "STMicroelectronics STLink Virtual COM Port" 和 "STM32 STLink" 即成功。
3. **串口助手**：任意（XCOM、SSCOM、或 Python pyserial）。波特率 **115200，8N1**。

### 5.2 打开工程与编译

1. 双击 `01_单片机代码_工作室_Qv1\Project.uvprojx`；
2. 菜单 **Project → Rebuild all target files**；
3. 底部 Build Output 必须显示 **0 Error(s), 0 Warning(s)**；
4. 同样操作再对 `Project_Sim.uvprojx` 做一次；
5. 检查两个 hex 逐字节一致（PowerShell 里：`Get-FileHash Objects\Project.hex; Get-FileHash Objects\Project_Sim.hex`，两个 SHA256 相同才算通过）。

> 命令行构建（写脚本用）：
> `UV4.exe -r Project.uvprojx -j0 -o build_main.log`

### 5.3 烧录

1. 用 4 线接好 ST-Link（SWDIO/SWCLK/GND/3.3V）；
2. 打开 ST-LINK Utility → Connect → 确认读到的芯片是 STM32F103C8；
3. 打开 `Objects\Project.hex` → **Program & Verify**；
4. ⚠️ 若软件弹"擦除方式"选项：**只选 Erase Sectors（按扇区擦除）**，严禁 Full Chip Erase（整片擦除）——参数页在 `0x0800FC00`（扇区 63），整片擦除会把标定参数全清掉；
5. 烧完点 Reset 复位，板子重启显示 "Qv1 Loops+Ports" 字样。

### 6.1 主流程（六段式，最新口径）

主循环每个阶段都是**事件驱动**（等事件，不空转死等），等事件期间心跳、按键、串口都照常工作：

1. **进轮判定**：首轮强制"普通"；之后读上光电原始电平，连续有效 ≥40ms → 判定"密料"；
2. **上报**：无条件发一帧串口 `MODE,NORMAL` 或 `MODE,DENSE`；
3. **料盘倒料**：料盘 POS_INIT → POS_LUMP → POS_INIT（每轮都做，给带1 供料）；
4. **带1 送料**：起带1 → 上光电触发 → 料延迟 → 停带1；
5. **带2 下料**：起带2 → 下光电触发 → **立刻停带2** → 发 `EVT,15` 通知上位机识别 → 等选箱命令 → 臂1 去箱子、臂2 拨料后回位 → 4 秒多余料检测预算 → 回环。

退出主循环：按住旋钮 **≥2 秒**（短按无效，防误触）。

### 6.2 错误码（屏幕上/串口里看到的数字含义）

| 码 | 含义 |
|---|---|
| 67 | ERR_SENS：等料超时 |
| 72 | ERR_BELT：传送带停滞 |
| 74 | ERR_PCA_FAIL：PCA9685 I2C 通信失败 |

## 7. 参数系统（掉电不丢的设定值）

### 7.1 存在哪里

参数页在 Flash `0x0800FC00`（扇区 63），共 **80 字节**，有魔数校验（`0xA55A5AAA`）和版本号（当前 `PARAM_VER = 7`）。上电时若发现版本不符，会自动整页恢复默认值（所以升级固件后参数会清零一次，属正常）。

**铁律**：参数页里**只放设定值**（位置角、速度、延迟、型号、细分、方向），**不放任何实时状态**（传感器电平、流程阶段这类运行时数据永远只在 RAM 里）。改参数结构体时必须同步：版本号 +1、sizeof 校验、串口参数码表、UI 菜单四样一起改。

### 7.2 参数表（菜单里能调的全部项目）

| 菜单页 | 内容 |
|---|---|
| 初始 | 臂1下 / 臂2上 / 料盘 三个初始角 |
| 箱子1~6 | 每个箱子的臂1 目标角 |
| 倒料 | 舵机2 / 料盘 倒料角 |
| 速度 | 舵机1 / 舵机2 / 料盘 运行速度（度/秒，30~180） |
| 传送带 | 两条带的速度、方向、细分（0/4/8/16/32） |
| 传感器 | 上/下光电的停带延迟（-1~990ms，步进 10） |

- 默认值：舵机1/2 速度 90、料盘 60、带速 5、传感器延迟 500ms。
- 舵机型号 180°/360° 由代码里 `kSrvTypeFixed` 固定（换型号要改代码并重新标定角度）。

## 8. 串口协议（上位机对接必读）

- 波特率 115200 8N1。
- 握手：上位机发 `0x54` → 板子回 `0xAB`（READY）。
- 命令帧：`0x53` 开头，`0x5C` 结尾；确认字节 `0x0F`。
- **动作码**（在 `Core/ProtoRx.h`）：

| 码 | 动作 |
|---|---|
| 2 | 启动主循环 |
| 3 | 取消/停止 |
| 4~9 | 选箱 1~6（识别完成后发这个） |
| 10 | 复位 |
| 11 | 急停回初始位 |
| 12 / 13 | 导出 / 导入参数 |

- **参数码**（`Core/ParamCode.h`，导入参数帧用）：1~24 位置角（8 槽 × 3 轴）、25~27 三轴速度、28~29 带速、30~31 带方向、32~33 传感器延迟、34~36 舵机型号、37~38 带细分。
- **主动上报**：每轮判定发 `MODE,NORMAL/DENSE`；识别时发 `EVT,15`；下光电检测到料后板子主动发 `0xAC → 0xD6 → 0xA3`（通知上位机"可以拍照了"，见 `Proto_SlaveShot`）。

## 9. 视觉识别系统（★ 这章是前任亲传的算法路线，照做）

### 9.1 核心思想（先把心态摆正）

**这不是"AI 项目"，是"算法项目"。** 网上大量教程教你把一个 YOLO 级模型塞进树莓派/边缘盒子，那是**错的路线**——分拣机只需要识别"形状 + 颜色"两个低维特征，根本不需要深度学习大模型上边缘设备。正确路线：

1. **训练在 PC 上做**，得到的是一个**很小的权重模型**（或几条规则）；
2. **推理时直接用训练好的权重**做轻量计算（PC 上位机做，或哪怕做个小模型导出都行）；
3. **不要**试图在单片机/边缘硬件里塞大模型，硬件跑不动不是硬件的问题，是方案的问题。

### 9.2 硬件布置

```
      摄像头（USB，俯拍，固定在识别托盘正上方）
            │
   ═══ 识别托盘（半透明/磨砂板） ═══
            │
   █████ 12V LED 发光板 █████   ← 由主控板控制开关
```

- **12V LED 发光板**放在识别托盘**正下方**，给料打背光，让料在相机里呈现为**黑色剪影**（背光剪影是后面形状识别的关键）。
- 发光板接 PCB，由 **STM32 主控控制**开/关。
- **摄像头必须选支持手动曝光/手动增益的**（廉价 USB 摄像头大多可以，用 OpenCV 的 `CAP_PROP_EXPOSURE` 等参数调）。自动曝光会被环境光带着漂，识别就废了。

### 9.3 识别流程（前任定稿的完整算法过程，逐步照做）

**第 1 步 · 触发**：料被送到识别托盘，传感器（上光电）检测到料。

**第 2 步 · 打光**：主控点亮 12V LED 发光板。

**第 3 步 · 黑白剪影定轮廓**：
- 摄像头程序先**调好黑白曝光**（拉低曝光/增益，让画面接近二值）；
- 在画面里**找到黑色区域**（背光剪影）；
- 用外接矩形**框住物体**，确定物体在托盘里的位置，并**初步判断形状**（长宽比、面积、圆度这类几何特征就能初步区分圆/方/三角）。

**第 4 步 · 关灯取色**：
- **关闭曝光和发光板**（让环境光成为唯一光源，颜色才真实）；
- 在刚才框出的物体区域内**均匀分点采样**——16 点、32 点、64 点都可以，**点越多越精确**（自己定，先 64 点起步）；
- 对每个采样点读取 RGB/HSV 值。

**第 5 步 · 去噪得到真实颜色**：
- 采样点里混着"环境颜色噪音"——主要是**托盘颜色**（框边缘的点可能采到托盘而非物体）；
- 用聚类/中值/距离阈值把离群点剔除（比如把接近托盘底色的点全部丢掉）；
- 剩下的点做平均，就是**物体的真实颜色**。

**第 6 步 · 形状+颜色分类**：
- 分类器随便选：**遗传算法、小神经网络、决策树（二分树）都行**——特征就两个维度（形状几何特征 + 颜色 HSV），这不是难题；
- 在 PC 上**训练好之后，直接用训练好的权重模型**做推理，不要重新训练、不要上重型框架。

### 9.4 训练数据怎么来（花小钱办大事）

- 训练样本：买**各种颜色的积木**，或者**自己建模、在网上下单 3D 打印**一批标准形状（立方体、圆柱、三角块……）。
- 拍照装置：**自己 3D 打印一个旋转云台**，把物体放上去，云台转、相机拍——一个物体一圈能拍几十张不同角度，数据集瞬间就有了。别花冤枉钱买"官方指定"的贵价道具。
- 数据越多越稳，但**先跑通 10 类 × 每个 50 张**，就能开工。

### 9.5 待补代码清单（★ 前任留白，你必须完成）

前任明确说：**下面这些程序还没有写进单片机，只交付了基础功能**，需要你（和你的队员）补上，**改完代码记得及时保存**：

1. **发光板控制程序**：STM32 控制 12V LED 发光板的开/关（建议用 MOSFET 低边开关，控制脚可用任一空闲引脚，如 PA4；12V 回路加续流保护）。建议做进主流程：上光电触发 → 开灯 → 通知上位机 → 等上位机识别完成 → 关灯。

4. **复位程序**：急停后的安全复位流程（舵机回初始位、状态机清零）。

## 10. 常见坑与铁律（前任踩过的，别重踩）

1. **光电极性**：高电平=有料（与直觉相反，因为外部电阻网络+固件口径共同决定）。接线先量电压，再上机。
2. **光电浮空**：外部上拉电阻缺失 → 无料时读低 → 一上电就狂判密料、带1 空转。上拉网络必须焊。
3. **选箱帧早到**：上位机如果在"识别进行中"（约 1.5s 窗口）发选箱命令，早期固件会丢帧卡死——现版本已加缓存，但你写上位机时仍建议：**收到 `EVT,15` 后再等 200ms 发选箱命令**，最稳。
4. **整片擦除**：会把参数页（0x0800FC00）清掉，机器所有标定归零。只允许 Erase Sectors。
5. **两个工程不同步**：只编了 Project 没编 Project_Sim，等于仿真和真机代码分叉。两工程必须同步、双 hex 逐字节一致。
6. **看门狗**：1 秒超时（IWDG，LSI 64 分频、重装 625），喂狗节流 100ms。你的新代码里**禁止出现超过 1 秒的阻塞等待**（长等待必须拆成事件驱动循环）。
7. **编码器按键**：PB15 高有效（按下接 3.3V）。换新旋钮模块时注意极性与板上的上拉/下拉配置。
8. **ST-Link 占用**：报 `LIBUSB_ERROR_ACCESS` / `open failed` 时，多半有残留 openocd 进程，任务管理器杀掉再连。
9. **GBK 编码**：工程源码是 GBK 编码（Keil 默认），用 VS Code 打开乱码时右下角切 GBK；不要在 UTF-8 下保存（会破坏注释）。
10. **改完必验证**：编译 0E/0W + 双 hex 一致 + 真机跑通，三样缺一不可，不许"看着没问题"。
11. **本板芯片发生过短路**：当前代码里的两个「奇怪之处」都是短路后的被迫妥协——①光电传感器改成**高电平=有料**（常规 NPN 对射是低有效）；②**心跳灯被移除**（PA0 恢复空闲）。**写新代码的三条注意**：a) 别把这两个妥协当成通用经验套到别处；b) 新功能选引脚前先断电量阻值确认无短路；c) 若日后重新制板修好短路，应将传感器改回低有效（`SENS_ACTIVE_LOW` 改回 1）并恢复心跳灯，让代码回到正常设计。

## 13. 给接手者的最后几句话

1. **先跑通，再优化**：第一目标是把机器复现出来、程序编译烧录成功、料能走完一圈。别上来就重构。
2. **分工干自己的部分**：机械、电控、识别三块边界清晰（本说明书就是按这个分的）。把自己那块做扎实、做可验证，就是对团队最大的贡献；队友的坑不要替他们跳，也不要被拖着跳。
3. **活用 AI 工具**：写代码、调算法时大胆用 AI 助手（Codex、DeepSeek 等支持 API 调用的主流工具都行），让它帮你写脚本、查报错、生成测试——但**自己必须能看懂它输出的每一行**，AI 是加速器不是替身。
4. **改了什么记什么**：每次改动写进 `Doc/`（新建一个版本说明 md：改了啥、为什么、编译数据、SHA256），后人会感谢你。
5. 遇到真解决不了的问题，去 `Doc/单片机工作流.md` 翻排查流程，那里有一套完整的调试方法论。

祝顺利。这机器上一任从零搭到能跑，花了两个多月；你照着这份文档，快得多。
